# 自定义娱乐 (astrbot_plugin_custom_entertainment)

一个集接口系统、每日运势、今日老公、今日人品、早安晚安、Minecraft Java 版检测、电脑状态、每日定时状态推送、每日读报、自定义词库、早晚安打卡排行、每日签到、偷积分、银行系统、坐骑商店、打工系统、宠物系统、发言统计、积分调整、整点报时、群员管理与数据备份于一体的娱乐插件。

所有功能都支持**按群独立开关与黑名单**，配置数据存放在独立文件、由独立页面管理。

## ✨ 功能模块

**1. 接口系统**
- 支持单参数和多参数（最多 5 个占位符）
- 支持关键词在前或在后，关键词和参数之间无需空格
- 支持 @ 在关键词前或后
- URL 模板可后台配置
- 占位符区分参数类型：
  - `{qq}` / `{qq1}` / `{qq2}` → 纯数字 QQ 号或 @某人，否则静默
  - `{text}` / `{text1}` / ... → 任意文本
  - `{pic}` / `{pic1}` / ... → 兼容旧配置，不校验类型
- 关键词无参数时不回复，参数个数不够时不回复
- 配置自动迁移老格式
- 接口列表：显示每条规则的参数类型、返回类型（图片/视频）和用法示例
- 支持无参数接口（参数个数填 0），也可返回视频自动发送到群

**2. 每日运势**
- 每人每天抽一次，当天固定，次日刷新
- 运势内容可在 WebUI 编辑
- 触发词可多个

**3. 今日老公**
- 每人每天抽一次，从群成员列表里随机抽，结果互不相同
- 只显示昵称与 QQ 头像（不再暴露 QQ 号）
- 可配置机器人是否参与随机，也可用排除列表屏蔽指定 QQ 号
- 新增「逼迫」指令：可强行指定某人为自己的老公
- 当天固定，次日刷新；已有老公时「逼迫」会提示冲突

**4. 今日人品**
- 每人每天抽一次，0‑100 分
- 当天固定，次日刷新
- 不同分数对应不同评价，带进度条

**5. 早安晚安**
- 全群统一打卡：不区分群，A 群打早安 B 群也算
- 记录每个用户每天的起床 / 睡觉时间
- 起床时显示睡眠时长；睡觉时显示清醒时长
- 必须当天打过早安才能打晚安
- 可配置最小清醒时长（默认 0）
- 逻辑日每日 6 点重置（最低 6 点）
- 早安打卡有效时间窗口（默认 12:00 截止）
- 晚安打卡时间限制（默认 23:59 截止）
- 支持自定义触发指令、分时段提示文案
- 支持重复打卡次数限制
- 自动记录历史打卡逻辑日集合，供其它模块统计连续打卡天数
- **早安 / 晚安打卡文案可在独立页面「数据管理 → 打卡系统」直接增删改**
  - 每条文案含「起始小时 / 结束小时 / 文案」，按打卡时间自动匹配
  - 内置 7 条早安 + 7 条晚安默认文案，首次运行写入数据文件后即可编辑

**6. Minecraft Java 版检测**
- 手动指令：MC版本，一键查询 Java 最新正式版与测试版
- 测试推送：手动拉取最新版本并推送（可在后台指定推送群，留空则推送给所有开启自动检测的群）
- 自动定时后台拉取，可设置检测间隔
- 支持按群开启/关闭自动版本推送
- 版本变更后自动在对应群推送更新通知
- 已移除 BE（基岩版）检测，避免 GitHub API 403 报错
- 主动推送使用原生 unified_msg_origin，确保消息真实送达群

**7. 自定义词库回复**
- 关键词命中就回复对应内容（关键词句首匹配）
- 支持后台 WebUI 增删改，支持换行回复
- 独立黑白名单控制词库生效群
- 支持单群屏蔽指定关键词

**8. 电脑状态查询**
- 查看 CPU / 内存 / 磁盘占用
- 显示插件版本、AstrBot 版本、系统版本
- 管理员指令

> **硬件数据来源（★ 本版本说明）**
>
> 所有硬件数据都用 **psutil** 获取 —— 它是 AstrBot 运行环境自带的库，
> **不需要任何额外的监控服务**。具体：
>
> | 项目 | 来源 | 说明 |
> |---|---|---|
> | CPU 占用 / 频率 / 分核占用 | `psutil` | 分核占用需要 0.2 秒采样 |
> | 内存占用 | `psutil.virtual_memory()` | 百分比 + 已用/共 |
> | 硬盘占用 | `psutil.disk_partitions/usage` | 按盘符列出 |
> | 开机时长 | `psutil.boot_time()` | |
> | 网络实时速率 | `psutil.net_io_counters()` | 用累计字节**差分**算，首次调用无基线不显示 |
>
> ⚠️ **本版本不提供** CPU **温度 / 功耗 / 电压 / 风扇**，以及**今日流量统计**：
> Windows 上 `psutil.sensors_temperatures()` 返回空，拿不到这些数据。
> 后台对应的开关打开时**该项不会显示**（不会输出「获取失败」之类的噪音）。

**9. 每日签到**
- 每人每天签到一次，无时间限制
- 积分随机 1‑1000，累计积分只增不减
- 展示：签到时间、连续天数、当天名次、今日发言数、本月签到天数、累计次数、今日获得、当前积分
- 签到排行：积分榜 + 连续榜 + 银行富豪榜，各前十
- 签到统计：不跟参数=查自己，@某人 / QQ号=查别人
- **签到统计只展示签到系统自己的数据**，**不包含打卡系统（早安晚安）的信息** ——
  两类统计各自独立（打卡数据见第 5 节「早安晚安」）
- **数据按群独立**：积分、银行、连续天数、累计次数与排行榜**每个群各自一套**，
  互不影响；数据结构为 `users[群号][用户号]`、`daily[群号][日期][用户号]`、
  `speaks[群号][日期][用户号]`，旧版扁平数据会自动迁到默认群下，不丢数据
- ⚠️ **注意：打卡系统（早安晚安）是「全群共享」的，不按群独立** ——
  它不分群，A 群打早安在 B 群也算（详见第 5 节）

**10. 偷积分**
- 指令：偷积分 @某人 / 偷积分 QQ号
- 随机偷取对方 1‑100 积分（可 WebUI 配置范围）
- 有概率成功/失败（默认 50% 成功率）
- 失败时有概率被对方反拿积分（默认 50%，范围 1‑100）
- 银行里的积分安全，不会被偷
- 反拿数量受限于攻击者当前持有积分
- 触发词、成功率、数量范围全部可自定义

**11. 银行系统**
- 指令：银行 / 存钱 数量 / 取钱 数量
- 支持 all 或 全部 一次存取所有
- 银行每天结算一次利息，默认日利率 1%
- 利息向下取整，不足 1 积分不结算
- 利息在每天配置小时后的首次触发时结算

**12. 坐骑商店系统**
- 消耗积分购买坐骑，查看个人坐骑收藏与骑乘状态
- 管理员后台可自定义多条坐骑：名称、购买价格、描述
- 支持指令查看坐骑商店列表、购买坐骑
- 坐骑数据持久保存，重启插件不丢失

**13. 打工系统**
- 多工种打工赚取积分，每个工种拥有独立冷却时间
- 管理员可后台增删工种，配置工种冷却小时、收益上下限
- 支持查看工种列表，执行打工获取随机区间积分
- 用户打工冷却状态随签到数据持久存储

**14. 整点报时**
- 按群独立开关，默认关闭，需要手动开启
- 支持手动指令开启 / 关闭本群，也支持管理员远程开关
- 默认整点报时（0‑23 全部整点），也可只报指定整点
- 支持自定义报时文案，可用 `{hour}` 占位符
- 每个整点每群只报一次，重启后保持状态
- 全部指令支持跨群远程操作（管理员）
- 新增「整点报时测试」指令：可随时手动触发一次推送，用于验证推送链路

**15. 每日读报**
- 手动指令：发送「每日读报」立即获取并发送今日 60s 读报，指令名可后台自定义多个（英文逗号分隔）
- 图片来源 `https://cyapi.top/API/60s.php?type=image`，图片不可用时自动回退为文字播报
- 支持每群定时推送：后台总开关 + 全局默认时间（默认 08:00）
- 时间支持整点（填 `8`）与精确到分钟（填 `08:30`），每个群可单独指定
- 支持远程开关与远程设置时间（均支持带群号）
- 按日期防重，同一天同一群只推一次

**18. 每日系列子菜单**
- `每日系列` 下有四个子菜单入口：

  | 入口 | 内容 |
  |---|---|
  | 运势功能 | 今日运势 / 运势 / 抽签 的用法与提示 |
  | 老公功能 | 今日老公 / 老公，以及 **逼迫 @某人**（强制指定） |
  | 人品功能 | 今日人品 的用法与提示 |
  | 读报功能 | 每日读报 的用法、定时推送说明、管理指令 |

- 子菜单里的指令名**跟随后台配置**动态显示（改了指令名，菜单同步变化）
- 子菜单**以纯文本发送**（本版本只有文字模式，见第 21 节）

**19. 更新日志指令（管理员）**
- `更新日志` —— 把最新更新发到群里

  | 用法 | 说明 |
  |---|---|
  | `更新日志` | **只显示最新一天**的更新（同一天多个版本一起显示） |
  | `更新日志 all` | 显示全部历史（最多 30 条，防刷屏） |

- **数据源是 `metadata.yaml` 的 `version_history` 段落**，运行时解析：
  更新 metadata.yaml 就等于更新日志，不会出现「指令显示与实际不符」
- **输出内容与 metadata.yaml 里写的一致**：正文按 `desc` 原样输出，
  只去掉 Markdown 标记，不截断、不改写
- 后台可配：指令名（支持多个）、标题文案
- 非管理员不可用；输出为纯文本

**20. 娱乐功能**

- 主菜单的 `娱乐功能` 入口，聚合猜数游戏等下挂功能
- ★★ 市场版说明：原版这里的「群名片 / 资料卡」已**整体移除**
  （它依赖本机渲染服务的 `/api/card` 接口，不是开箱可用的功能）

**21. 输出模式（★ 本版本仅支持文字模式）**

> ⚠️ **重要说明**：这个市场版**只支持文字输出**，没有图片模式。

- 所有内容类输出（运势 / 老公 / 人品 / 打卡 / 签到 / 排行 / 发言统计 /
  银行 / 坐骑 / 打工 / 偷积分 / 宠物 …）、**全部菜单**、以及
  **定时推送**（整点报时 / 电脑状态 / MC 版本 / 每日读报）
  一律**以纯文本发送**
- **不需要任何本地渲染服务**，装了就能用，不会出现
  「图片模式没反应 / 渲染失败回落」这类问题
- 「老公」这类角色卡片会以**文字 + 头像图片**的形式发送
- 后台的「输出模式」相关配置在本版本**不生效**，
  留着只是为了跟原版配置兼容（升级/降级时不会丢设置）

**为什么去掉图片模式？**

图片渲染依赖一个额外的本地服务（把文字排成卡片图）。
为了让插件**开箱即用、不引入外部依赖**，本版本移除了该功能。

> 💡 如果你需要图片/卡片效果，请使用**作者的完整版**，
> 或自行部署渲染服务后改用完整版插件。

**17. 宠物系统**
- `购买宠物` / `我的宠物 [页码]` / `出售宠物`（返还 75%）/ `放生宠物` / `宠物商店 [页码]`
- **我的宠物**：每页 **20 只**，用「我的宠物 页码」翻页；
  每只占两行（第一行名字 / 属性 / 等级，第二行血量 / 体力 / 攻击 / 防御 / 经验 / 冒险状态）
- **宠物商店规则**：每种宠物**每人都能买一只**（不再「本群只能一个人买」），
  各自独立生成属性与五行；同一个人重复买同一只仍会被拦（每人每种限一只），
  商店列表里只标「你已拥有」，不再标注「已被购买」
- `宠物查看` / `宠物冒险` / `宠物休息` / `宠物决斗 @对方` / `宠物上班`
- **不带宠物名时**：`宠物上班` / `宠物冒险` 会让**名下所有宠物一起出勤**，
  每只各自随机一个事件（互相独立），末尾给出「出勤 N 只，未出发 M 只」统计；
  带宠物名则仍然只跑那一只（输出格式与原来一致）。
  在冷却 / 体力不足 / 血量过低的会逐条列出原因并跳过，不影响其它宠物
- **全部一起冒险 / 上班时的显示限制**：**所有宠物都照常结算并保存**
  （冷却、体力、血量、经验、积分一个不少），但详细记录**只显示前 10 只**，
  其余用「…… 其余 N 只的记录已省略」带过，避免刷屏
  （冒险与上班规则一致，条数由 `BATCH_SHOW` 控制）
- `物品商店` / `购买物品` / `使用物品`；管理员 `添加宠物` / `删除宠物`
- 满级 100，五行（金木水火土）互相克制有伤害加成，冷却按小时
- **属性与五行都在购买时按购买者 QQ 随机生成**，商店与图鉴不展示
- **内置 57 条上班事件 + 56 条冒险事件**，全部存于数据文件，
  可在独立页面「宠物功能」里增删改（事件描述 / 经验区间 / 积分区间 / 额外掉血）
- 冒险事件支持 `hp_cost`（额外掉血），实际扣血 = 全局 `pet_adventure_hp_cost` + 事件自带值，
  所以「撞见巨蟒」这类危险事件代价更高、回报也更大

**18. 积分调整（作弊，管理员专用）**
- `加积分 @某人 数量` / `减积分 @某人 数量`，指令名可后台自定义多个
- 只能管理员 / 群主 / 群管使用，非管理员静默不响应
- 支持直接写 QQ 号；扣积分到 0 为止不会变负

## 🎉 彩蛋：运势 vs 人品
运势和人品是两套完全独立的算法，互不干扰，所以有概率出现「玄学组合」，比如：
- 运势：凶 ★★☆☆☆☆☆ ，人品：85/100 ✨ 大吉大利
- 签文：见异思迁，十九不成
- 解签：开始全情投入，到后面却不能坚持，事情总是在这种情况下失败……

所以今天到底该不该出门？🤔
常见组合：
- 大凶 + 大吉：「玄学对冲，全看命硬不硬」
- 大吉 + 大凶：「表面风光，实际一塌糊涂」
- 大吉 + 大吉：「今天你就是天选之子」
- 大凶 + 大凶：「建议直接躺平」

本插件不提供人生建议，抽到什么全看脸 🎲

2. 群内群主 / 群管理员 → 群内管理指令权限

## 🎛️ 功能开关说明
- 不再有全局开关。每个群的功能开关互相独立，默认全部开启。
- 用「功能状态」查看当前群（或指定群）各功能开关。
- 用「开启功能 运势」/「关闭功能 运势」调整当前群。
- 用「开启功能 运势 群号」/「关闭功能 运势 群号」远程调整。
- 整点报时是独立开关，用「整点报时开 / 整点报时关」控制。

| --- | --- | --- |

## ⚙️ WebUI 可配置项

> 所有配置修改后重启 AstrBot 生效，部分配置支持热重载

1. 指令自定义：全部功能触发词可自行修改，包含 5 个子菜单指令、整点报时指令、MC测试推送指令、整点报时测试指令
2. 黑白名单：全局群黑白名单、各子功能独立黑白名单
3. 表情包 API 模板管理，支持多模板添加
4. 词库管理，增删自定义问答
5. 运势内容自定义编辑
6. 早安晚安配置：打卡逻辑起始小时、早安截止小时、晚安截止小时/分钟、最小清醒时长、重复打卡最大提醒次数、分时段早安 / 晚安提示语
7. MC 版本检测配置：自动检测间隔、自动推送群管理、MC 测试推送指定群（留空则推送给所有已开启自动检测的群）
8. 打卡排行榜指令自定义、打卡统计指令自定义
9. 签到指令：签到 / 签到排行 / 签到统计三组指令自定义（英文逗号分隔多个），签到群黑白名单
10. 偷积分配置：启用开关、触发词、偷取范围、成功率、失败反拿概率、反拿范围
11. 银行配置：启用开关、触发词、存/取钱触发词、日利率、利息结算小时
12. 整点报时配置：启用开关、轮询间隔、默认报时文案、全部指令自定义（含整点报时测试）
13. 打工系统配置：启用开关、打工指令、打工列表指令、工种列表（冷却、收益范围）、添加工种指令、删除工种指令
14. 坐骑系统配置：启用开关、查看坐骑指令、坐骑商店指令、购买坐骑指令、坐骑列表（名称、价格、描述）、添加坐骑指令、删除坐骑指令

16. 每日状态推送配置：总开关、全局默认推送时间（HH:MM）、后台检查间隔、4 个推送指令自定义（开启 / 关闭 / 设置时间 / 查看列表）
17. 每日读报配置：总开关、全局默认读报时间（HH:MM，支持整点或精确分钟）、后台检查间隔、手动读报指令与 4 个推送管理指令自定义
18. 数据备份与还原：独立页面右上角「💾 导出数据」按钮，可备份到服务器指定目录、下载 JSON 到本机；

## 🧩 数据存储说明

- 用户打卡记录、词库、表情包规则、群配置全部以 json 文件持久化存储在插件 data 目录
- 旧版本数据自动迁移，升级插件无需手动删除历史记录
- 存储采用临时文件原子写入，防止异常断电导致 json 损坏
- 签到数据存于 `astrbot_plugin_custom_entertainment_checkin.json`
- 签到数据额外包含 `bank`（银行余额）与 `last_interest_date`（利息结算日）
- 打卡数据存于 `astrbot_plugin_custom_entertainment_greeting.json`
- 打卡数据额外包含 `greeting_days`（已打卡逻辑日列表，最多保留最近 400 天），用于计算连续打卡天数
- 整点报时数据存于 `astrbot_plugin_custom_entertainment_hourly_chime.json`
- 整点报时数据新增 `umos` 字段，保存每个群的 `unified_msg_origin`，用于主动推送
- MC 数据存于 `astrbot_plugin_custom_entertainment_minecraft.json`
- MC 数据新增 `umos` 字段，保存每个群的 `unified_msg_origin`，用于主动推送
- 昵称缓存存于 `astrbot_plugin_custom_entertainment_nickname.json`，跨群共享 QQ 昵称，用于排行榜展示
- 每日状态推送数据存于 `astrbot_plugin_custom_entertainment_status_push.json`，包含各群开关与推送时间（`groups`）、防重记录（`last_push`）与推送通道（`umos`）
- 发言统计数据存于 `astrbot_plugin_custom_entertainment_speak_stats.json`，结构为 `groups[群号][用户号]`，含每日发言次数（`days`）、累计（`total`）、连续活跃（`streak`/`best_streak`）
- 数据集合（接口规则/运势/词库/坐骑/工种/早晚安文案/宠物图鉴/上班事件/冒险事件/物品等 11 组）存于 `astrbot_plugin_custom_entertainment_data.json`，结构为 `collections[集合名]`
- 宠物数据存于 `astrbot_plugin_custom_entertainment_pet.json`，结构为 `groups[群号]`，含 `pets`（每人宠物：等级/经验/血量/体力/攻防/五行/冷却）与 `items`（道具背包）
- 宠物的**属性与五行都在购买那一刻按购买者 QQ 随机生成**（同一玩家结果稳定、不同玩家各不相同）；商店、图鉴与后台编辑器都不展示属性
  不再依赖「桌面版标记」，也不会连带影响 AstrBot 的 pip／依赖管理行为
  （只设 `ASTRBOT_ROOT`，不动 `ASTRBOT_DESKTOP_CLIENT`）。

  **兜底保护（插件侧）**：万一还有残留，插件启动时会自动清理，带多重安全校验 ——
  真数据目录必须存在、路径不得与数据目录重叠、发现 `data/plugin_data/` 就按兜底数据
  放弃清理、只认 AstrBot 特征文件
